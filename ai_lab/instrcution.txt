Zappy Lab Environment: Antigravity CLI & Server SpecificationThis document defines the architecture, rules, and technical implementation details for the Python-based mock server environment designed to test and refine Zappy AI clients.1. Project OverviewThe objective is to establish a local, deterministic, and highly observable lab environment ("Antigravity Server") that mimics the exact behavior of the official Zappy network game server. This environment facilitates rapid prototyping, debugging, and regression testing of AI clients without needing the full C/SFML project stack.Winning ConditionThe game takes place on the toroidal planet Trantor. The winning team is the first to have at least 6 players reach the maximum elevation level (Level 8).2. World Mechanics & EnvironmentGeographyMap Dimensions: Defined by $X$ (width) and $Y$ (height) via a configuration file.Toroidal Topology: The map wraps around seamlessly in all four directions.Moving off the right edge ($X-1$) places the entity at the left edge ($0$).Moving off the top edge ($0$) places the entity at the bottom edge ($Y-1$).Distance and sound propagation formulas must account for the shortest path across these wrapping boundaries.Resource DistributionResources spawn at initialization and regenerate every $20/f$ simulated seconds. Concurrency Model (Asynchronous Pygame)To avoid threading synchronization hazards, Pygame and network I/O share the same asyncio event loop.The core execution uses an async def main_loop() structure.At the end of every frame rendering step, the code invokes await asyncio.sleep(0.001). This yields micro-slots of CPU time to the asyncio.start_server network drivers to digest incoming TCP buffers without blocking frame rates.Decoupled Time EngineTime steps do not map directly to wall-clock time. This enables simulation controls such as pausing and fast-forwarding:Delta Calculation: Every frame tracks the real time elapsed since the prior iteration ($dt$).Virtual Progression: The virtual time increment is calculated as virtual_dt = dt * f_current * execution_multiplier.If the environment state is shifted to PAUSED, virtual_dt is forced to 0. Network commands are still received and buffered, but internal game clocks, resource counts, and movement actions freeze.Configuration Format (config.json)JSON{

Lab Inspection & UI LayoutThe UI prioritizes raw data visibility and state extraction over graphical polish.Visual Rendering ProtocolGrid Resolution: Rendered as clean, low-contrast bounding squares.Resource Visualization: Grouped inside tiles as tiny fixed colored blocks with a textual count counter overlay (e.g., a green pixel block followed by text x4 to signify 4 food units) to maintain grid cleanliness.Player Tokens: Rendered as solid geometric triangles. The primary vertex indicates the direction the player is looking (North, East, South, West). The fills map cleanly to distinctive team color configurations.Diagnostic Side Panel & InteractivitySelection Focus: Utilizing Pygame's vector click detection (pygame.mouse.get_pos()), clicking any cell sets that coordinate or resident player as the "Selected Focus Object".Dashboard Output: The right segment of the interface maps explicit metrics for the selected entity:Player Context: Unique connection ID, assigned Team Name, current Level, precise position $(X, Y)$, Orientation angle.Metabolism Monitor: Remaining food stores, calculated simulated ticks surviving until absolute starvation event occurs.Inventory Payload: Direct count matrix of all 6 stone classifications.Command Queue Tracking: A deep list showing the exact order of the up to 10 stacked strings, along with a counting timer displaying simulated seconds remaining before the current command executes.Global HUD Information: A top-aligned overlay constantly shows the current f constant, total concurrent AI client count, elapsed game time ticks, and a highly visible visual marker when PAUSE mode is active.
